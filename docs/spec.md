# 需求规格草案

**项目名称**　南京工业职业技术大学产业数据库与人才需求预测系统  
**项目简称**　AI 产业人才需求分析与预测平台  
**状态**　待评审  
**作者署名**　待确认  
**草案日期**　2026-11-27

## 背景与目标

项目面向南京工业职业技术大学计算机与软件学院（人工智能学院），服务软件工程专业及 AI 协同开发方向。首期正式建设和验收覆盖**专业动态调整、课程内容更新、实践项目建设**。三个场景共享产业数据库、岗位技能分析和人才需求预测能力，贯通数据采集、分析预测、教学资源建设与报告输出。

**课程更新提交与审批按原文纳入首期。** 教师在平台内提交课程更新建议，专业负责人负责审批。以下建设内容与验收草案依据原文的建设目标、角色权限表及指标 1、指标 2 编排。原始项目需求文档

## 术语表

| 术语 | 定义 |
|---|---|
| 产业人才主题数据库 | 汇聚企业、岗位、招聘需求和技能信息，形成企业库、岗位库、招聘需求库和技能库。 |
| 岗位技能标签 | 从岗位文本中识别的技能、工具和工程能力，用于热度、趋势和关联分析。 |
| 人才需求预测 | 通过至少 1 个预测模型，支持岗位、技能、区域和时间等维度分析，并输出趋势、排行和预警结果。 |
| AI 协同课程体系 | 面向软件工程专业及 AI 协同开发方向的课程体系，交付时包含相应知识技能点。 |
| 项目案例与实践资源 | 覆盖软件工程全环节、供教师下载使用的教学资源。 |

## 用户与角色

| 角色 | 原文规定的职责 |
|---|---|
| 专业负责人 | 查看分析与预测结果，审阅并确认专业调整建议，审批课程更新。 |
| 教师 | 查询岗位技能与趋势，下载课程和项目资源，提交课程更新建议。 |
| 数据分析员 | 配置采集任务、管理数据质量、校正标签、编制报告。 |
| 系统管理员 | 维护用户和角色、配置参数、调度任务、执行备份与恢复。业务数据审批由相应业务角色处理。 |
| 审计员 | 只读查看操作日志和登录审计，导出审计报表。 |
| 安全管理员 | 参与三员分立。具体授权范围由校方确认。 |

## 范围边界

**In Scope**　面向江苏、浙江、上海、安徽的软件和信息技术服务业，支持省、市维度配置。首期范围包括产业数据采集与治理、多维查询和看板、岗位技能分析、人才需求预测、专业调整建议、课程与项目资源、课程更新提交与审批、年度分析报告及系统权限管理。

**Out of Scope**　目标地域和行业以外的数据建设与业务验收。

## 业务不变量

- 数据通过合法来源采集或导入。每条数据记录保留来源渠道、采集时间、原始链接或出处，支持核对。
- 功能和数据访问受角色授权约束。系统管理员、安全管理员、审计员实行三员分立，关键操作实行双人复核。
- 年度交付采用原文口径：**每年专业调整建议及配套项目清单不少于 4 项**。计数单位由校方确认。

## 核心场景与功能需求

| 场景 | 触发条件与主流程 | 业务规则与异常 |
|---|---|---|
| `SCN-01` 专业动态调整 | 开展专业年度调整时，专业负责人查看岗位、技能和预测结果，审阅并确认调整建议，核对配套项目清单。 | 按年度交付要求核对建议及清单。低于原文数量要求时，该项验收不通过。 |
| `SCN-02` 课程内容更新 | 教师查询岗位技能与趋势，结合课程体系和知识技能点提出更新建议，在平台内提交，由专业负责人审批。 | 提交与审批按角色权限执行，具体审批规则由校方确认。越权操作应受权限约束。 |
| `SCN-03` 实践项目建设 | 建设实践教学资源时，结合岗位技能与预测结果形成项目案例和实践资源，供教师下载使用。 | 资源覆盖软件工程全环节。验收时按校方确认的环节清单核对覆盖情况。 |

| 编号 | 功能需求 |
|---|---|
| `REQ-01` | 汇聚企业、岗位、招聘需求、技能、工具、工程能力、区域及时间数据。支持多源合法采集、模板导入、接口接入、定时更新、增量更新和手工补录。 |
| `REQ-02` | 检测缺失、重复和异常数据，支持清洗规则、分类、标签、质量评分、处理台账及来源追溯。 |
| `REQ-03` | 按省市、企业、岗位、技能和时间等维度组合查询，提供统计汇总、趋势分析、图表和看板。 |
| `REQ-04` | 从岗位文本智能抽取技能、工具和工程能力，支持标签管理及热度、趋势、关联分析。 |
| `REQ-05` | 提供至少 1 个人才需求预测模型，支持岗位、技能、区域和时间趋势等维度分析，输出趋势、排行和预警，支持持续评估与优化。 |
| `REQ-06` | 提供专业调整建议及配套项目清单，支持专业负责人审阅和确认，满足原文年度交付要求。 |
| `REQ-07` | 交付 1 套 AI 协同课程体系及知识技能点，支持课程内容和知识技能点迭代。 |
| `REQ-08` | 支持教师提交课程更新建议、专业负责人审批课程更新。 |
| `REQ-09` | 交付覆盖软件工程全环节的项目案例和实践资源，支持教师下载。 |
| `REQ-10` | 支持分析报告和年度报告输出，提供 Word、PDF、Excel 等导出格式。 |
| `REQ-11` | 支持功能权限、数据权限、操作日志、登录审计、审计报表和关键操作双人复核。 |

## 验收标准

| 编号 | Given | When | Then |
|---|---|---|---|
| `AC-01` | 有合法来源的招聘数据及来源说明 | 执行采集、导入或更新 | 数据汇入相应主题库，可以核对来源渠道、采集时间和出处。 |
| `AC-02` | 输入包含缺失、重复或异常记录 | 执行数据质量检查与处理 | 可核查识别结果、处理记录和质量评分，并追溯对应原始数据。 |
| `AC-03` | 主题库已有符合范围的数据 | 按省市、企业、岗位、技能或时间组合查询 | 查询、汇总、趋势图和看板与所选范围一致。 |
| `AC-04` | 岗位文本包含技能、工具和工程能力信息 | 执行岗位技能分析 | 生成相应标签，可查看热度、趋势和关联结果。 |
| `AC-05` | 有可用于模型验收的数据 | 运行人才需求预测 | 至少 1 个模型可运行，支持规定维度分析，能够输出趋势、排行和预警结果，并支持评估。 |
| `AC-06` | 到达年度交付核查节点 | 核对专业调整建议及配套项目清单 | 专业负责人可审阅和确认建议，交付数量按原文要求核查为不少于 4 项。 |
| `AC-07` | 课程资源已交付 | 核查课程体系及知识技能点 | 可查阅 1 套 AI 协同课程体系及配套知识技能点。 |
| `AC-08` | 教师和专业负责人分别具备相应授权 | 教师提交课程更新建议，专业负责人审批 | 平台支持完成提交与审批，两个操作受对应角色权限约束。 |
| `AC-09` | 项目案例与实践资源已交付 | 按校方确认的软件工程环节清单核查 | 资源覆盖全部规定环节，教师可下载使用。 |
| `AC-10` | 已生成分析或年度报告 | 选择原文要求的报告格式导出 | 可获得 Word、PDF、Excel 等相应格式的报告。 |
| `AC-11` | 用户权限受限，或操作需要双人复核 | 请求访问受限数据或发起关键操作 | 系统限制越权访问，关键操作按双人复核规则处理，审计员可只读核查相关日志。 |

## 非功能需求

支持校内指定环境部署、通过校园网使用浏览器访问，并提供标准接口扩展能力。数据应安全、可追溯，支持定时备份及恢复演练。性能及可用性量化指标待确认。

## 外部依赖与约束

- **首期已提供的真实招聘数据来源**是 CnOpenData 岗位样本。样本包含 7 张来源表、318 条含岗位名称的记录，其中 268 条含发布日期或发布时间，可用于核对字段、数据处理与技能抽取。CnOpenData 岗位样本
- 校方负责确认课程试点、课程材料、用户授权、审批规则及部署环境。

## 风险、假设与待确认项

- **数据与预测**。样本的发布日期分布存在断档。预测验收所需的数据覆盖、评估标准及预警触发条件待确认。
- **教学资源与年度交付**。软件工程全环节的核对清单、年度不少于 4 项的计数单位、试点课程及课程资料待校方确认。
- **权限与流程**。安全管理员的具体授权、关键操作清单和课程审批规则待校方确认。
