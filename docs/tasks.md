业务与验收采用 [spec.md](./spec.md)，服务、接口与里程碑采用 [plan.md](./plan.md)，数据库归属、实体和约束采用 db-design.md。实施遵守 [constitution.md](../constitution.md) 和 [AGENTS.md](../AGENTS.md)。表中的工程、源码和测试模块是实施目标位置，模块名称沿用方案部署单元。

## 执行规则

- 依赖列给出直接前置 Task ID 及待解除的阻塞项。每个 Task ID 对应一个主要改动单元。
- 对业务行为、契约和交互，先编写并运行失败测试。测试名称或描述带对应 `AC-*`，确认在预期行为断言失败后，再实施显式依赖它的任务。原用例及相关回归通过后留存证据。已评审结构迁移、工程骨架以构建、启动及集成核查为证据。
- `[P]` 只用于依赖已就绪且主要写入范围互不冲突的任务。当前工程骨架与运行依赖尚待核查，清单暂未标记。实施时核对实际依赖、共享配置及迁移写入范围，再判断可并行项。
- 校方确认、数据供应及设计补正按下表逐项解除。涉及权威文档或环境变更时按治理文件取得授权。各项功能验收按自己的证据单独判断。
